# Module notes

- Module 0: Django, PostgreSQL, health endpoint, and the React/Tailwind scaffold run locally.
- Module 1: the frontend uses a central API client, real shop cards and map, shop details, queue status, and authentication screens.
- Module 2: shops, barbers, services, and owner profiles are stored in PostgreSQL; Haversine search and opening/wait calculations power nearby results.
- Module 3: customer queue joins and cancellation are protected by database constraints and transactions.
- Module 4: JWT roles, owner queue controls, walk-in throttling, no-show release, stale-data labels, and polling are implemented.
- Module 5: frontend pages use the backend API for shops, login, queues, owner actions, QR walk-ins, and assistant search.
- Module 6: Dockerfiles, Compose health checks, pytest, and Locust load testing are provided.
- Module 7: the rule parser supports service names, English/Hinglish terms, price caps, time windows, and ranking preferences.
- Module 8: architecture, deployment notes, interview questions, and progress are documented.
